# ChatGPT 左侧悬停侧栏与备用导航

直接安装的 Tampermonkey 油猴脚本，无需构建。桌面端加载页面时收起左侧栏，鼠标停留在最左侧 60px 区域 100ms 后展开，离开侧栏 500ms 后收起。

更新记录见 [CHANGELOG.md](CHANGELOG.md)。

进入已保存的会话后自动读取当前分支的完整问题索引，无需先滚到顶部。点击未渲染的问题会自动滚动触发页面加载，再按消息 ID 确认位置。

## 安装

1. 浏览器安装并启用 Tampermonkey，允许它在 ChatGPT 网站运行。
2. 禁用之前的侧栏脚本，避免两个脚本同时操作按钮。
3. 打开[脚本安装地址](https://raw.githubusercontent.com/Alex-hj/myTampermonkeyScripts/main/chatgpt-hover-sidebar/chatgpt-hover-sidebar.user.js)，由 Tampermonkey 安装。也可以在控制面板新建脚本，复制本目录 `chatgpt-hover-sidebar.user.js` 的全部内容并保存。
4. 刷新 ChatGPT 页面。若完全无效，检查 Tampermonkey 是否显示该脚本正在运行，以及浏览器是否允许扩展运行用户脚本。

## 行为

- 使用 ChatGPT 自己的展开/收起按钮，保留页面原有布局和右侧导航，不覆盖页面全局 CSS。
- 监听动态 DOM，并每 1.2 秒进行一次补偿检查；页面加载超过 6 秒也继续等待。
- 点击后检查侧栏状态，React 尚未接管按钮时会继续尝试。
- 屏幕外、隐藏、右侧或弹窗内的按钮不作为左侧栏开关。
- 无论手动打开、悬停打开或页面自动展开，鼠标移出侧栏都会收起；不再区分打开来源。
- 鼠标在侧栏内部时保持展开；重命名等编辑期间、菜单或弹窗打开时暂停收起。普通按钮保留焦点不会阻止收起。
- 窄屏及触摸设备不自动操作左侧栏。备用导航在宽度小于 900px 时隐藏。

## 右侧导航

默认采用“自动”模式：识别到可见的原生右侧导航时隐藏备用导航，原生导航消失超过 2 秒且存在问题消息时显示备用导航。不会删除、隐藏或改写原生导航节点。

点击 Tampermonkey 扩展图标可选择：

| 菜单 | 用途 |
| --- | --- |
| ✅ 右侧导航：自动（优先原生） | 默认模式，检测不到原生导航时显示备用版本（当前模式带 ✅ 标记） |
| ○ 右侧导航：强制显示备用 | 原生导航虽然存在但无法点击时使用 |
| ○ 右侧导航：关闭备用 | 仅使用原生导航，或自动检测出现误判时使用 |
| 重新读取完整会话索引 | 立即重试历史读取，或在切换回答分支后主动刷新 |
| 立即收起左侧栏 | 手动触发一次收起 |
| 查看脚本状态 | 打开诊断窗口，查看侧栏识别和历史请求错误；点击“一键复制”可发送诊断文本 |

模式选择会保存。菜单和持久化使用 [Tampermonkey 官方 API](https://www.tampermonkey.net/documentation.php)。

备用导航默认居中显示紧凑短横线，一条对应一个用户问题，当前问题的横线加深。鼠标移入后向左展开圆角列表，逐行显示问题标题，长标题单行省略；当前问题和鼠标经过的行分别高亮。点击滚动定位，移出 160ms 后恢复缩略状态，延时内移回会取消收起。

展开列表可独立滚动，支持深浅主题。键盘 Tab 进入时自动展开，方向键/Home/End 切换条目，Enter 或空格定位，Esc 收起。正常读取或同步时不显示状态文字，保持界面清爽；错误和定位提示仍会显示。消息仅通过 `textContent` 显示，不解析为 HTML。

可直接打开 [本地外观预览](tests/navigation-preview.html) 检查短横线、悬停列表和深色主题。预览使用示例问题，不访问聊天接口。

完整索引只增强备用导航，原生导航的历史加载行为不作修改。如果原生导航仍只显示已加载消息，请选择“强制显示备用”。

## 完整历史与定位

- 在当前 ChatGPT 域名内读取 `/api/auth/session`，使用当前登录会话读取该会话的历史；令牌只在请求链内存中使用，不保存到油猴存储，不输出到日志，不发送给 GitHub 或其他第三方。
- 从页面启动时观察原生 `fetch` 的当前会话 GET 请求。只提取 `chatgpt-account-id`、`oai-device-id` 两个请求头，并在该会话的主动读取中复用；设备 ID 也可从当前站点的 `oai-did` cookie 获取。不扫描或尝试其他工作区。
- 页面本身成功返回完整消息树时，读取响应副本建立索引，保留页面原响应。观察不改变原请求、返回值或异常；不读取其他域名、其他会话或聊天发送请求。
- 页面返回新版分页格式时，校验第一页的分页信息；有更早历史则复用第一页并继续请求后续页，不能把 `/messages?before=…` 中间页标记为完整会话。
- 旧消息树接口返回 403 时只补试一次新版分页入口；分页入口同样拒绝后退避，401 和 429 仍直接停止本轮读取。不同接口的请求均使用当前登录会话，不切换账户或工作区。
- 403 仍然表示服务端拒绝：补齐当前请求信息并不保证解决所有 403，脚本不会绕过登录验证或权限检查。诊断窗口仅显示设备/工作区信息是否存在，不复制其值或令牌。
- 优先读取 `include_full_conversation=true` 的消息树，从 `current_node` 沿父节点回溯，保留当前分支并校验链路完整性；不兼容时先尝试不带参数的普通消息树接口。
- 消息树接口不可用或只返回部分数据时，尝试新版会话分页接口，沿 `before` 游标读取更早消息，按 ID 去重；循环游标、缺失分页信息或超过 200 页都不会标记为完整。
- 索引成功后不随 DOM 卸载而删除。新增问题立即补充，并触发延迟刷新；每分钟重新读取一次以同步分支变更。失败后采用 30 秒至 5 分钟的退避重试。
- 未加载消息根据已挂载消息的先后顺序搜索：距离较远时逐步加速，单步最多 16 屏；接近目标时改为小步滚动，越过目标后减半并限制后续步幅，不用问题数量比例估算像素位置。正文消息挂载会提前唤醒搜索，无变化时低频检查；到达边界或窗口暂时清空时等待页面加载。
- 找到目标后重新匹配消息身份，仅滚动正文容器并预留顶部空间；页面重排或节点被替换时继续校正，连续至少两次检查且稳定至少 400ms 后确认定位。已对齐时不重复滚动。诊断中的“定位滚动”和“耗时”可用于比较实际会话的跳转表现。
- 支持消息自身、嵌套元素和轮次容器的 ID；重复问题不会仅凭摘要匹配到其他消息。可通过“查看脚本状态”确认最近定位是否已成功、已取消或超时。
- 定位最多等待 45 秒；Esc、手动滚轮、触摸、点击或切换会话会取消定位。超时会提示重试，不会假装已跳转成功。
- 会话切换会中止旧请求，并丢弃迟到响应和上一会话残留的消息节点。

后台自动读取或同步时不展示加载提示；若接口失败则显示读取失败错误原因。接口失败时保留已有索引/已加载问题，不把它宣称为完整历史。可通过“查看脚本状态”查看错误状态码、观察到的会话响应次数和最近响应格式；仅显示“页面请求观察：已启用”不代表已经成功捕获数据。

## 配置与兼容范围

脚本中的 `CONFIG`（源码位于 `src/config.js`）可调整触发宽度、展开/收起延迟和最小桌面宽度。

ChatGPT 的 DOM 会随版本、账号实验和语言变化。脚本识别常见 `data-testid`、中英文侧栏标签和关联 `aria-controls`；无法保证覆盖所有页面版本。没有可靠识别到按钮时保持等待，不会猜测点击其他功能按钮。

原生导航检测依赖语义属性和右侧位置，无法证明其内部点击功能是否正常；未知结构可能漏检，其他右侧导航也可能导致误判。可以手动切换模式，或把已确认的 CSS 选择器填入 `nativeNavigationSelector`。强制显示模式会与仍可见的原生导航共存，可能占用相同位置。

完整历史依赖 ChatGPT 网页内部接口，不是稳定的公开 API。未登录、临时会话、分享链接、工作区权限限制或接口变更时可能只能显示已加载内容。图片/附件问题使用占位标题。

定位仍依赖 ChatGPT 自己加载并挂载历史 DOM；极长会话可能需要重试。脚本不会把自行生成的历史消息插入聊天正文。备用导航是相近交互的独立实现，不是对某一版原生导航的像素级复制。

接口适配参考：[会话分页与完整性说明](https://github.com/bujue3709/GPT-Conversation-Toolkit/blob/main/README.en.md)。

## 源码结构

`src/` 按职责拆成 ES 模块，`npm run build` 用 esbuild 打包成单个 `chatgpt-hover-sidebar.user.js`。产物不压缩、保留中文字符串，但源码里的注释不会进入产物。安装和自动更新使用的始终是这个产物，用户不需要构建。

- `main.js`：入口，注册监听并启动刷新循环；`scheduler.js`：刷新调度。
- `sidebar-*.js`：左侧栏识别、开关点击、悬停控制与暂停收起的保护判断。
- `history-*.js`、`request-*.js`、`native-index.js`：历史索引读取与页面请求观察。
- `navigation-*.js`、`native-navigation.js`：右侧备用导航。
- `jump.js`、`scroll-geometry.js`：点击问题后的滚动定位。
- `diagnostics.js`、`menus.js`：诊断窗口与油猴菜单。
- `config.js`、`state.js`、`utils.js`、`conversation.js`、`entries.js`：常量、运行状态与公共工具。
- `header.txt`：UserScript 元数据头，`@version` 在这里维护。

## GitHub 发布与自动更新

已配置 `Alex-hj/myTampermonkeyScripts` 的 `main` 分支 Raw 地址作为 `@updateURL` 和 `@downloadURL`。脚本的 `@name` 和 `@namespace` 保持不变。

1. 修改 `src/` 后运行 `npm run build` 重新生成 `chatgpt-hover-sidebar.user.js`。产物必须和源码一起提交，测试会检查两者是否同步。
2. 发布新版本时只需手动修改 `src/header.txt` 的 `@version`，再运行 `npm run bump`：它以该版本号为准，同步 `package.json`、`package-lock.json`，并重新构建脚本。然后在 `CHANGELOG.md`、`GREASYFORK.md` 补充更新说明，运行 `npm test` 验证后提交、推送。不需要压缩或发布 npm 包。
3. 推送形如 `v1.2.9` 的版本标签（`git tag v1.2.9`，再 `git push origin v1.2.9`）后，GitHub Actions 会先校验标签与 `@version` 一致，再检查、测试、构建，并把 `chatgpt-hover-sidebar.user.js` 上传到同名的 GitHub Release。油猴自动更新仍读取 `main` 上的文件，与 Release 无关。
4. 用户需要开启 Tampermonkey 的脚本更新检查，并能访问 `raw.githubusercontent.com`。检查按油猴设置的周期执行；手动检查更新可以立即验证。安装更新后刷新 ChatGPT 页面。

不要把更新地址改成固定 commit 或版本 tag；保持指向 `main` 上相同的文件路径。仅修改 `package.json` 的版本不会触发油猴更新。

## 开发验证

```powershell
cd chatgpt-hover-sidebar
npm.cmd ci --ignore-scripts --cache .npm-cache
npm.cmd run build
npm.cmd run check
npm.cmd test
```

测试按主题拆在 `tests/*.test.cjs`，共用夹具在 `tests/support.cjs`；GitHub Actions 会在推送到 `main` 和 Pull Request 时自动运行检查与测试，推送 `v*` 版本标签时还会发布 Release。测试在 jsdom 模拟页面中验证动态加载、点击重试、所有打开来源的移出收起、原生导航保护和备用导航行为。模拟 DOM 不代表已在登录后的 ChatGPT 实站通过验证。

实站验收：刷新已展开侧栏的页面；从左边缘移入/移出；手动打开侧栏；打开侧栏会话菜单；切换会话并发送新问题；检查原生导航；通过扩展菜单强制显示备用导航并点击定位。
